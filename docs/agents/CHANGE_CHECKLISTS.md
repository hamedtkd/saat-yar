# چک‌لیست تغییرات حساس ساعت‌یار

این سند برای جلوگیری از جاافتادن مسیرهای مهم در تغییرات چندفایلی است. فقط بخش مرتبط با تغییر را کامل کنید و نتیجه را در Pull Request بنویسید.

## ۱. Schema، Migration و داده ذخیره‌شده

- [ ] مشخص شده است که تغییر روی قرارداد Persisted data اثر دارد یا ندارد.
- [ ] در تغییر ناسازگار، Schema version افزایش یافته است.
- [ ] Migration مرحله‌ای از نسخه قبلی وجود دارد.
- [ ] Factory مرکزی `AppData` و مقادیر پیش‌فرض به‌روزرسانی شده‌اند.
- [ ] Normalization داده ناقص و قدیمی را امن می‌کند.
- [ ] Backup validation و Restore با قرارداد جدید هماهنگ‌اند.
- [ ] Recovery، Snapshot و Merge بررسی شده‌اند.
- [ ] IndexedDB و مسیر بارگذاری اولیه بررسی شده‌اند.
- [ ] متادیتای Envelope وارد State برنامه نمی‌شود.
- [ ] داده ناشناخته یا کلید قدیمی با تصمیم صریح مدیریت می‌شود.
- [ ] تست Migration از داده قدیمی و Round-trip اضافه شده است.
- [ ] `npm run audit:schema` پاس شده است.

## ۲. تنظیمات، Draft و ناوبری

- [ ] حالت مشاهده بدون ویرایش ناخواسته باز می‌شود.
- [ ] Draft از داده ذخیره‌شده مستقل است.
- [ ] ذخیره و انصراف رفتار روشن دارند.
- [ ] ذخیره خودکار خاموش باعث Commit ضمنی نمی‌شود.
- [ ] Dirty State در جابه‌جایی بخش، Route، تاریخ و Back/Forward محافظت می‌شود.
- [ ] متن Dialog نام بخش یا تغییر حل‌نشده را روشن بیان می‌کند.
- [ ] Focus trap، Escape و بازگشت Focus بررسی شده‌اند.

## ۳. رابط، Responsive و Accessibility

- [ ] موبایل و دسکتاپ بررسی شده‌اند.
- [ ] تم روشن و تاریک بررسی شده‌اند.
- [ ] RTL، Alignment و ترتیب خواندن درست است.
- [ ] رنگ متن و پس‌زمینه Contrast کافی دارند.
- [ ] Keyboard navigation و Focus قابل مشاهده‌اند.
- [ ] Reduced motion رعایت شده است.
- [ ] Empty، Loading، Error و Disabled state بررسی شده‌اند.
- [ ] برای تغییر بصری Screenshot یا ویدیو تهیه شده است.

## ۴. تست و قرارداد معماری

- [ ] تست رفتار عمومی را می‌سنجد، نه نام متغیر یا شکل موقت کد را.
- [ ] Regex سورس فقط برای قانون پایدار معماری یا مخزن استفاده شده است.
- [ ] Fixture مشترک به‌جای ساخت ناقص مدل دامنه استفاده شده است.
- [ ] تست شکست واقعی را بازتولید می‌کند.
- [ ] تست فقط برای سبزشدن ضعیف یا حذف نشده است.
- [ ] فایل Production جدید تا حد امکان زیر ۲۵۰ خط است.
- [ ] Importهای محلی و Dependencyهای مستقیم معتبرند.

## ۵. انتشار و تحویل

- [ ] `npm run check:quality` پاس شده است.
- [ ] `npm run check:release` پاس شده است یا محدودیت محیط دقیق ثبت شده است.
- [ ] Routeهای مرتبط دستی مرور شده‌اند.
- [ ] Backup/Restore برای تغییر داده‌ای تست شده است.
- [ ] Changelog یا Release Notes در صورت نیاز به‌روزرسانی شده است.
