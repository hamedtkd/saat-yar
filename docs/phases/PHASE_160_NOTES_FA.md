# فاز ۱۶۰ — قرارداد ناهار و ساعت خروج

این فاز پس از Release تاریخی `v2.3.1` انجام می‌شود و Tag/Manifest آن Release را تغییر نمی‌دهد.

## مسئله

در تنظیمات قبلی، عبارت «هدف هفتگی» به‌راحتی با مدت حضور اشتباه می‌شد. همچنین تغییر `lunchMinutes` یک روز، در حالی که ساعت پایان ثابت می‌ماند، هدف کار خالص همان روز را تغییر می‌داد. وضعیت «ناهار با حقوق» هم فقط روی رکورد روز قابل تغییر بود و پیش‌فرض برنامه کاری نداشت.

قرارداد مورد انتظار برای یک روز با ۸ ساعت کار خالص و ناهار بدون حقوق:

- ورود `07:30` + ناهار `45m` → خروج پیشنهادی `16:15`
- ورود `07:15` + ناهار `45m` → خروج پیشنهادی `16:00`
- ورود `07:15` + ناهار واقعی `25m` → خروج پیشنهادی `15:40`
- ورود `07:30` + ناهار واقعی `30m` → خروج پیشنهادی `16:00`

## قرارداد محاسبه

`plannedExit = actualStart + netWorkTarget + unpaidLunch + unpaidBreaks - creditedLeave`

اگر ناهار «با حقوق» باشد، مدت ناهار از کارکرد کسر نمی‌شود و خروج پیشنهادی را عقب نمی‌برد. اگر بدون حقوق باشد، مدت واقعی ناهار همان روز به زمان لازم برای خروج اضافه می‌شود.

## تغییرات UI و تنظیمات

- نام فیلد به «هدف کار خالص هفتگی» شفاف شد.
- کنترل «ناهار پیش‌فرض برای همه روزها» اضافه شد.
- مدت ناهار را می‌توان یکجا برای کل هفته اعمال کرد.
- وضعیت «جزو کارکرد (با حقوق)» را می‌توان یکجا برای همه روزها تعیین کرد؛ خاموش یعنی ناهار از کارکرد خالص کم می‌شود و خروج را به اندازه مدت واقعی ناهار عقب می‌برد.
- تغییر جمعی یا روزانه مدت/نوع ناهار، ساعت پایان را جابه‌جا می‌کند تا کار خالص قبلی حفظ شود.
- امکان Override روزانه در ویرایش رکورد همچنان باقی است.
- لایه نتایج جستجوی تنظیمات بالاتر از Sidebar چسبان قرار گرفت تا Sidebar روی نتیجه های جستجو نیفتد.

## داده و سازگاری

- `WorkScheduleDay.lunchPaid` به‌صورت optional و backward-compatible اضافه شده و مقدار داده‌های قدیمی `false` نرمال می‌شود.
- Schema اصلی روی `v17` باقی می‌ماند؛ Release تاریخی `v2.3.1` و Manifest آن تغییر نمی‌کند.
- رکورد جدید پیش‌فرض ناهار را از schedule همان روز می‌گیرد؛ رکوردهای قبلی تغییر داده نمی‌شوند.

## تست‌های Regression

فایل `tests/phase160-lunch-workday-contract.test.ts` هفت قرارداد جدید را پوشش می‌دهد: چهار مثال واقعی خروج، ناهار با حقوق، semantics برنامه، حفظ هدف هنگام تغییر ناهار، bulk settings، wiring UI/record و ترتیب لایه جستجوی تنظیمات نسبت به Sidebar. همچنین قرارداد قدیمی Responsive فاز ۵۰ با چیدمان سه بخشی جدید فاز ۱۶۰ همگام شد.
