# فاز ۱۷۲ — ساعت زنده Runtime و Refresh کم‌مصرف

## مسئله

اگر ساعت‌یار برای مدتی باز می‌ماند و کاربر بدون Reload به تب برمی‌گشت، بعضی زمان‌های در حال اجرا همان مقدار Render قبلی را نشان می‌دادند. منبع داده درست بود، اما UI فقط هنگام تغییر State دوباره محاسبه می‌شد و در نتیجه حس «اپ متوقف شده» ایجاد می‌کرد.

## قرارداد Runtime

- یک Scheduler مشترک برای کل برنامه وجود دارد؛ هر Component تایمر مستقل نمی‌سازد.
- تایمر اصلی کارمند و تایمر پروژه با cadence یک‌ثانیه‌ای نمایش زنده `ساعت:دقیقه:ثانیه` دارند.
- Summaryها، Metricها و مالی پروژه فقط در مرز دقیقه Refresh می‌شوند تا محاسبات سنگین‌تر هر ثانیه تکرار نشوند.
- Scheduler از `setTimeout` هم‌تراز با مرز ثانیه/دقیقه استفاده می‌کند؛ شمارنده تجمعی ندارد و بعد از Sleep از `Date.now()` واقعی Sync می‌شود.
- وقتی `document.visibilityState !== "visible"` است، Timer فعال کاملاً لغو می‌شود. با `visibilitychange`، `focus` یا `pageshow` مقدار واقعی فوراً Sync می‌شود.
- هیچ Tick زمان، IndexedDB، BroadcastChannel، Network، Service Worker یا Heartbeat را نمی‌نویسد.
- اگر حداقل یک مصرف‌کننده ثانیه‌ای فعال باشد فقط یک Scheduler ثانیه‌ای در کل برنامه اجرا می‌شود؛ Listenerهای دقیقه‌ای فقط در مرز دقیقه Notify می‌شوند.
- نشان «زنده» از `motion-safe:animate-pulse` استفاده می‌کند تا Reduced Motion محترم بماند.

## قرارداد محاسبه زنده

نمایش زنده با محاسبه نهایی رکورد یکی نیست و قرارداد تاریخی Payroll را تغییر نمی‌دهد:

- ناهار برنامه‌ریزی‌شده قبل از شروع واقعی ناهار از تایمر زنده کم نمی‌شود.
- ناهار بدون حقوق فقط از زمان واقعی ثبت‌شده آن کسر می‌شود؛ ناهار با حقوق کسر نمی‌شود.
- وقفه بدون حقوق از مدت واقعی آن کم می‌شود و وقفه با حقوق تایمر کار را متوقف نمی‌کند.
- رکورد پایان‌یافته همچنان از `calc` تاریخی/نهایی استفاده می‌کند.
- `calcLive` فقط برای رکورد باز، `worked/credited/balance` را با زمان Runtime تازه می‌کند و Schema یا داده Persisted را تغییر نمی‌دهد.

## سطوح UI

- Today Focus: تایمر اصلی کارمند و پروژه به‌صورت ثانیه‌ای زنده است.
- Today Smart Summary و Today Metrics: کارکرد، پیشرفت و حقوق/درآمد جاری در cadence دقیقه‌ای تازه می‌شوند.
- Project List و Project Detail: زمان، بودجه و درآمد پروژه دارای تایمر باز در cadence دقیقه‌ای تازه می‌شوند.
- Employee Browser Smoke ثابت می‌کند تایمر کارمند بدون Reload واقعاً جلو می‌رود.

## داده و سازگاری

- AppData Schema همچنان v17 است.
- Migration جدیدی وجود ندارد.
- Dependency جدیدی اضافه نشده است.
- قرارداد Heartbeat/Session Recovery فاز ۱۶۳ تغییر نمی‌کند.
- قرارداد Timer Ownership و Multi-tab تغییر نمی‌کند.

## ادامه

فاز ۱۷۳ آنبوردینگ را بر اساس Employee/Freelancer/Hybrid شخصی می‌کند و Import Wizard فاز ۱۷۱ را به‌عنوان مسیر اختیاری «داده قبلی دارم» در Flow راه‌اندازی وارد می‌کند.
