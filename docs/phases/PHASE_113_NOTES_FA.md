# فاز ۱۱۳ — پروتکل امن انتقال دستگاه‌به‌دستگاه

## هدف

ساخت لایه انتقال مستقل از UI و Transport برای جابه‌جایی داده ساعت‌یار بین لپ‌تاپ و موبایل بدون دیتابیس مرکزی. این فاز عمداً QR و WebRTC را پیاده نمی‌کند؛ فاز ۱۱۴ همین پروتکل را روی Pairing واقعی سوار می‌کند.

## قرارداد انتقال

- پروتکل مستقل با شناسه `saatyar-device-transfer` و `protocolVersion: 1`.
- Payload شامل `AppData` کامل، نسخه Schema فعلی، شناسه انتقال، زمان ایجاد و هویت غیرحساس دستگاه مبدأ است.
- SHA-256 روی نسخه canonical payload ذخیره می‌شود تا دست‌کاری یا خرابی انتقال قبل از Import شناسایی شود.
- Payload با قرارداد Backup/Schema فعلی دوباره Parse می‌شود؛ دستگاه قدیمی‌تر بسته با Schema جدیدتر را رد می‌کند.

## Preview و تعارض

قبل از هر تغییری می‌توان این موارد را نمایش داد:

- تعداد رکوردهای محلی و ورودی هر Collection؛
- تعداد آیتم‌های جدید؛
- تعارض رکورد روزانه بر اساس تاریخ؛
- تعارض Collectionهای شناسه‌دار بر اساس `id`؛
- تغییر Settings به‌عنوان تعارض مستقل.

هیچ Previewای داده محلی را mutate نمی‌کند.

## اعمال انتقال

دو روش اصلی وجود دارد:

- `replace`: داده دستگاه مقصد با AppData دریافتی جایگزین می‌شود.
- `merge`: آیتم‌های جدید اضافه می‌شوند و برای تعارض می‌توان صریحاً `keep-local` یا `use-incoming` را انتخاب کرد.

این تصمیم باید در UI فاز ۱۱۴ قبل از Commit نهایی به کاربر نمایش داده شود.

## رمزنگاری نشست

- برای هر Pairing یک کلید تصادفی ۲۵۶ بیتی تولید می‌شود.
- رمزنگاری با Web Crypto و `AES-GCM-256` انجام می‌شود.
- IV برای هر بسته تصادفی است.
- Envelope رمزنگاری‌شده AppData را به‌صورت plaintext حمل نمی‌کند.
- کلید نشست فقط برای Pairing کوتاه‌عمر طراحی شده و نباید در IndexedDB دائمی ذخیره شود.

## اصلاح Release Gate آفلاین

Smoke تست آفلاین دیگر کل Network Stack مرورگر را با CDP خاموش نمی‌کند؛ آن روش در Windows می‌توانست خود Context مرورگر را ناپایدار کند و با وجود Service Worker سالم timeout بدهد. اکنون پس از تأیید precache، سرور Static موقت متوقف می‌شود و همان صفحه با `Page.reload` دوباره بارگذاری می‌شود. بنابراین آزمون همچنان قطع واقعی Origin را بررسی می‌کند ولی ارتباط CDP سالم می‌ماند.

## ایمنی

- این فاز Schema را تغییر نمی‌دهد؛ AppData همچنان v17 است.
- Dependency جدیدی اضافه نشده است.
- Transport هنوز انتخاب نشده؛ بنابراین WebRTC/QR/Signaling هیچ couplingای به Domain ندارد.
- پروتکل قابل استفاده برای QR چندبخشی، WebRTC DataChannel یا حتی فایل موقت است.
