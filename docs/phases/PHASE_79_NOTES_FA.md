# فاز ۷۹ — تفکیک معماری Persistence و هماهنگی چند تب

## هدف

رفع شکست Quality Gate ناشی از عبور `use-persisted-app-data.ts` از سقف ۲۵۰ خط و جداکردن مسئولیت هماهنگی چند تب از مسئولیت ذخیره و بازیابی داده.

## تغییرات

- ایجاد Hook مستقل `use-multi-tab-data-sync.ts`.
- انتقال BroadcastChannel، دریافت پیام، وضعیت تعارض، تاریخچه رخدادها و بارگذاری نسخه خارجی به Hook جدید.
- نگه‌داشتن ذخیره IndexedDB، Recovery، Heartbeat نشست و وضعیت آنلاین در Hook اصلی.
- ارائه API محدود برای انتشار ذخیره، مصرف Skip Persist و اکشن‌های سلامت همگام‌سازی.
- کاهش Hook اصلی از ۲۵۱ خط به کمتر از سقف معماری.
