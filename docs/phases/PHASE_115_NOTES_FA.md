# فاز ۱۱۵ — QR محلی برای Pairing دستگاه‌ها

این فاز تجربه انتقال دستگاه‌به‌دستگاه فاز ۱۱۴ را از Copy/Paste صرف به Pairing سریع با QR ارتقا می‌دهد و هم‌زمان خطای TypeScript گزارش‌شده در `device-transfer-card.tsx` را می‌بندد.

## رفع رگرسیون TypeScript فاز ۱۱۴

شرط UI قبلی پس از Narrow شدن `pairing.role` دوباره آن را با `"sender"` مقایسه می‌کرد و TypeScript 5.9 آن را مقایسه‌ای غیرممکن می‌دانست. شرط به قرارداد واقعی `idle | receiver` ساده شد؛ هیچ Cast یا خاموش‌کردن TypeScript اضافه نشده است.

## QR کاملاً Local

Pairing Code شامل Offer/Answer و در Offer شامل کلید موقت Session است. برای همین تولید QR نباید به API شخص ثالث متکی باشد. ساعت‌یار یک QR encoder محلی vendored با مجوز MIT دارد و SVG را مستقیماً داخل مرورگر می‌سازد؛ هیچ درخواست شبکه‌ای برای QR انجام نمی‌شود.

## QR چندفریمی

SDP واقعی WebRTC ممکن است از ظرفیت یک QR واحد بزرگ‌تر شود. ساعت‌یار Pairing Code را به فریم‌های مستقل با قرارداد `SYQR1` تقسیم می‌کند. هر فریم شامل Batch ID، شماره قطعه، تعداد کل و Checksum است. نمایشگر فریم‌ها را خودکار می‌چرخاند و اسکنر موبایل قطعات را حتی با ترتیب متفاوت جمع می‌کند. تنها پس از دریافت همه فریم‌ها و تأیید Checksum، Pairing Code کامل به جریان WebRTC تحویل داده می‌شود.

## اسکن دوربین

اسکن در صورت وجود `BarcodeDetector` با دوربین پشت دستگاه انجام می‌شود. تصویر دوربین از صفحه خارج نمی‌شود و به سرور ارسال نمی‌شود. اگر مرورگر BarcodeDetector یا Camera API مناسب نداشته باشد، Copy/Paste و Share Link فاز ۱۱۴ همچنان فعال هستند.

## امنیت

QR همان Bearer Secret کوتاه‌عمر Pairing است و نباید عمومی منتشر شود. QR رمزنگاری جایگزین AES-GCM انتقال داده نیست؛ فقط Signaling و کلید Session موقت را بین دو دستگاه جابه‌جا می‌کند. خود AppData همچنان پس از اتصال روی DataChannel به‌صورت AES-GCM منتقل می‌شود.
