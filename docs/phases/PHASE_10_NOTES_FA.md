# فاز ۱۰ — ذخیره مقاوم و بازیابی محلی

این فاز روی جلوگیری از گم‌شدن داده‌ها در صورت خطای IndexedDB یا کمبود فضای مرورگر تمرکز دارد.

## تغییرات

- نمایش وضعیت واقعی ذخیره در Header: در حال ذخیره، ذخیره شده یا خطا
- ثبت زمان آخرین ذخیره موفق
- نگه‌داری Snapshot بازیابی مستقل در Local Storage پیش از ذخیره اصلی
- ساخت Snapshot اضطراری در صورت شکست IndexedDB
- امکان تلاش دوباره برای ذخیره
- ساخت دستی نسخه بازیابی
- بازگردانی نسخه بازیابی محلی
- حذف نسخه بازیابی
- پاک‌سازی Snapshot نامعتبر
- تست round-trip و اعتبارسنجی Snapshot

## نکته معماری

نسخه بازیابی جزو `AppData` نیست و در schema اصلی ذخیره نمی‌شود؛ بنابراین این فاز به Migration جدید نیاز ندارد و schema همچنان نسخه ۱۱ است.

نسخه بازیابی محلی جای فایل Backup دانلودی را نمی‌گیرد، چون با پاک‌شدن داده‌های مرورگر ممکن است آن هم حذف شود.
