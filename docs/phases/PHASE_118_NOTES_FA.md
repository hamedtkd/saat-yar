# فاز ۱۱۸ — Browser E2E و پالیش نهایی Sync

## هدف

بستن مسیر انتقال بین دو دستگاه بعد از سبزشدن کامل Quality Gate فاز ۱۱۷ و تبدیل تست مرورگر WebRTC از یک پیام ساده به انتقال رمزنگاری‌شده چندبخشی نزدیک‌تر به قرارداد واقعی ساعت‌یار.

## تغییرات UX

- نمایش مسیر چهارمرحله‌ای انتقال: انتخاب مسیر، تبادل QR، اتصال مستقیم و ارسال/ادغام.
- اسکن QR دیگر به کلیک تأیید اضافه نیاز ندارد؛ Offer روی گیرنده و Answer روی فرستنده بلافاصله مرحله بعد را اجرا می‌کنند.
- وضعیت `completed` به نشست اضافه شد تا پایان واقعی انتقال از صرفاً «متصل» بودن قابل تشخیص باشد.
- بعد از ACK فرستنده یا اعمال Merge/Replace روی گیرنده، نشست به حالت تکمیل‌شده می‌رود.
- گیرنده می‌تواند Preview را بدون اعمال داده رد کند و نشست را امن ببندد.
- Copy/Paste و Share Link همچنان fallback رسمی باقی مانده‌اند.

## Browser E2E

`npm run test:browser:pairing` اکنون فقط یک رشته آزمایشی ارسال نمی‌کند. Smoke مرورگر واقعی:

1. دو `RTCPeerConnection` واقعی می‌سازد.
2. DataChannel مرتب `saatyar-transfer` را باز می‌کند.
3. Payload نمونه را با AES-GCM رمزنگاری می‌کند.
4. Envelope را به چند chunk با اندازه نزدیک قرارداد Production تقسیم می‌کند.
5. `start/chunk/end` را روی WebRTC ارسال می‌کند.
6. سمت مقابل chunkها را مونتاژ و Payload را رمزگشایی می‌کند.
7. ACK همان `transferId` را برمی‌گرداند.
8. تست تأیید می‌کند انتقال واقعاً چندبخشی بوده است.

این Smoke همچنان opt-in باقی می‌ماند و به `check:release` اضافه نشده تا CIهای محدود از نظر ICE/WebRTC باعث False Negative نشوند.

## داده و Schema

- AppData Schema همچنان v17 است.
- Migration جدیدی وجود ندارد.
- Backup format تغییر نکرده است.
- هیچ Payload یا Session Key جدیدی در Storage پایدار ذخیره نمی‌شود.
- Dependency جدیدی اضافه نشده است.
